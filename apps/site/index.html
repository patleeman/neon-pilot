What it is

A local workbench where the harness itself is part of the agent's workspace.

Neon Pilot is not another hosted chat surface. It is a local runtime around the agent: transcript storage, provider settings, workspace context, background execution, extension hosting, browser control, MCP tools, terminal access, telemetry, and reusable workflow surfaces.

Use it when the agent should be able to change the harness around the work: add a page, wire a tool, expose a setting, schedule a follow-up, or turn a repeated workflow into a first-class local extension.

Feature set

The pieces a self-extensible harness needs.

Neon Pilot is built around the full loop: gather local context, choose the right provider, run tools, inspect output, continue in the background, and let agents turn useful patterns into reusable extensions.

Beyond extensible

Self-extensible means the agent can grow the harness while it works.

Traditional extensible software asks the user to install packages or spend serious engineering time inside a framework. Pi moved the model forward by making the agent self-extensible: it can build extensions for itself and then run with them.

Neon Pilot carries that idea into a full desktop client. Extensions are not just skills and hooks: they can own pages, sidebars, workbench panels, settings, backend actions, setup readiness items, tools, commands, storage, transcript rendering, and provider behavior.

Extension-first

Keep core small. Make the product out of extensions.

Neon Pilot's product surface is built around bundled, optional, and user extensions. Inspired by Pi's extension architecture, a capability can contribute pages, sidebar views, settings, commands, agent tools, skills, setup readiness items, and backend actions without bloating the runtime core.
