The benchmark supports task-level delegation through full vertical slices. It does not support handing every roadmap item to Flash without review. Codex review remained economically useful: it found a scoped-state persistence bug, two false-green feature results, and one release-smoke residue that the task checks missed.

Historical replay setup and harness debugging consumed more Codex work than normal delegation will. The benchmark cost should therefore be used to compare task outcomes and worker capability, not as a direct estimate of steady-state orchestration overhead.

## Recommended delegation policy

1. Default Flash implementation lanes to level-2 subsystem tasks or level-3 vertical slices with complete outcome contracts and focused validation ownership.
2. Delegate level-4 and level-5 work selectively when the work is mechanically coherent: subsystem removal, API propagation, migration, repetitive test backfill, or a phase with a strong existing pattern.
3. Split coupled product work that combines a new public contract, backend data model, visible UI, and lifecycle automation unless one owner path already unifies those concerns.
4. Keep one Codex semantic review before integration. Green tests were insufficient for the Home widgets and combined desktop-search tasks.
5. Give at most one concrete failure-oriented nudge. Promote or take back the work when the repaired result still misses the product contract.
6. Track accepted implementation, Codex repair, elapsed time, and cost. Do not optimize for raw Flash activity or line count.

## Harness findings

The run found and corrected these evaluation issues:

- Pi `message_update` events repeat the growing partial message and produced a 1.7 GB log. The runner now stores only completed messages, tool results, turn endings, and session markers.
- Historical worktrees need built workspace packages and the system extension manager before route/UI tests.
- Setup builds can modify historically tracked generated extension artifacts. The runner records and restores those setup-owned changes before Flash starts.
- Worker-created untracked files and staged `git rm` deletions must be included in patch and changed-line accounting.
- Full historical test files may already fail on the base commit. Hidden gates must target the owning behavior or carry explicit baseline evidence.
- Automated green checks require Codex semantic review; reference diff similarity remains evidence, not the grading target.
