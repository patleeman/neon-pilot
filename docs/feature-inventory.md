# Feature Inventory

This is a user-perspective inventory for QA planning. It is not a coverage report yet. The
coverage column is deliberately a placeholder until each feature is mapped to an explicit
coverage method and measurement.

Source pass date: 2026-06-24.

## How to Use This Inventory

- **Owner** separates core platform surfaces from bundled system extensions.
- **User feature** names what a user or external agent can actually do.
- **Current test hooks** lists obvious automated tests, smoke scripts, or docs found during the audit.
- **Coverage** is `TBD` until a later pass assigns a percentage from concrete assertions or coverage data.
- **QA notes** call out app-path, visual, live integration, or manual checks that should not be inferred from unit tests.
- Live app-path QA must inspect the whole composed viewport, including inactive split panes and restored workbench tabs.
  A raw stack trace in any visible panel is a finding even when the primary route/control works.

Primary validation command families found during the audit:

| Scope                       | Command                              |
| --------------------------- | ------------------------------------ |
| All Vitest tests            | `pnpm test`                          |
| Full repository check       | `pnpm run check`                     |
| Extension static gates      | `pnpm run check:extensions:static`   |
| Extension smoke tests       | `pnpm run test:extensions`           |
| Release hardening tests     | `pnpm run test:release-hardening`    |
| Release doctor              | `pnpm run check:release:doctor`      |
